# Project bug audit — 12 November 2026

This audit covers the current native C#/WPF worktree, browser companion, persistence, uploads, media/audio/device integrations, settings, updater, startup registration, build scripts and installer. Three service reviewers worked with the separate UI, optimization and documentation teams through the shared local agent log. Existing uncommitted changes were preserved.

## Confirmed fixes

| Trigger | Corrected behavior | Regression evidence |
| --- | --- | --- |
| Native browser host repeatedly disconnects before its handshake | Retries increase from 1 to 30 seconds; media heartbeats respect the pending retry; protocol readiness restores the initial delay | Actual shipped service worker in an isolated JavaScript realm, including synchronous failures and manual recovery |
| A companion regression fails before the browser-safety check succeeds in CI | Both Node commands have explicit exit checks, so a later passing command cannot mask a failure | Both fixtures run locally; workflow command and evidence paths reviewed |
| An ICS property contains a quoted URI parameter with a colon | The parser finds the delimiter outside quoted parameters and retains the actual description | Quoted URI/timezone fixture plus persisted organizer reload |
| An imported event has `STATUS:CANCELLED` | It is skipped instead of becoming an active agenda event | Actual calendar parser fixture |
| An all-day event has a saved timezone offset different from Windows | Agenda, export and editor retain its civil date; timed events retain local-time display and their instant | Opposite-offset store/export fixtures and actual native editor Save |
| An upload response supplies only a share URL | The share URL remains usable; a direct-file URL is available only when the response actually supplies one | In-memory HTTP responses covering share-only, direct-only, invalid and missing HTTPS links |
| A shelf path changes between a folder and a regular file | Detail, local status and upload eligibility read the current path type | Five actual WPF rebind and upload admission/rejection assertions, including preservation of hosted links |
| A delayed Spotify request fails after disconnect | The request cannot restore stale available-player state or overwrite the explicit disconnected status | Delayed refresh/playback response fixtures |
| Spotify sign-in finishes after cancellation, disconnect or disposal | Stale completion is rejected before saving credentials or announcing a connection | Delayed authorization fixtures plus a successful encrypted save/reload control |
| An update plan contains explicit null values or invalid paths | Validation rejects it through the normal error contract before process handoff | Serialized malformed-plan fixtures |
| The original app has exited and the installer fails to launch | Recovery may restart the original app; a live parent or active installer prevents a duplicate/racing restart | Process-free stage-policy assertions; actual process behavior belongs to disposable-VM verification |
| Uninstall sees startup registrations owned by a later portable copy | It removes only this executable's task/Run records and preserves unrelated records and the saved preference | XML/command ownership fixtures and added disposable-VM mixed-ownership scenarios |

The coordinated UI audit also fixes canonical shelf upload selection, direct-link menu availability, Cancel/Enter handling in the calendar editor, failed reminder/world-clock save feedback, footer keyboard traversal, device countdown suspension behind the chooser, pinned-window recovery, constrained settings layout and organizer contrast. Timeline tooltips now refresh when duration or seeking availability changes within the same elapsed second. These native assertions are included in the integrated application suite.

## Verification

The existing `--self-test` entry point invokes the new data, media and updater fixtures under the unchanged private-desktop isolation guard. In-memory HTTP handlers make no external upload or Spotify calls. Native editor tests use local WPF controls; they do not inject global input.

Before/after console evidence is retained locally under `artifacts/project-bug-audit/`: the data fixtures reproduce seven original failures and pass thirteen fixed assertions; the Spotify fixtures reproduce seven failures and pass sixteen fixed assertions, including actual encrypted persistence; updater/startup source copies compile and pass their process-free policy checks.

The final integrated private application gate passes **1,535 assertions**, with zero failures and eight informational records. The final public self-contained installer payload gate passes **1,534 assertions**, with zero failures and eight informational records. Both embedded private/public updater metadata checks pass, preserving the public default. The final public gate's 152 frozen build inputs match the current worktree with zero changed, missing or new input differences. Browser checks pass 25 companion assertions and all eight isolation-guard scenarios on the same final source inputs.

The installer compiles with Inno Setup 6.7.4 and .NET SDK 8.0.427. Its SHA-256 sidecar matches the generated bytes: `3C62409B250C8B6D6A2C028ABF40CD71E4C69D30BD219E0A57736A65FE9165AE`. It is retained locally for verification. Exact manifests, reports, compiler provenance, package checksum and source-drift audits are saved under `artifacts/project-bug-audit/installer-gate2/`.

The initial complete review covered 101 production, browser, automation and build/configuration paths. Late reviews covered every subsequent changed production path plus the new progress sampler and performance comparison script. They caught the folder-classification regression above and an incorrect direct-link response in a new upload test; both were corrected before the final gates. An unmeasured change to hidden spectrum-bar smoothing was reverted. The final gates include the coordinated performance changes; earlier passing reports remain historical evidence. Six isolated controlled performance runs also pass 98 checks each; their measurements and limits are recorded in [PERFORMANCE.md](PERFORMANCE.md).

Full installation, rollback, upgrade and uninstall checks must run in a disposable Windows VM. `scripts/Verify-Installer.ps1` now exercises mixed startup ownership using the exact uninstall command. These new VM scenarios have not been executed on the development machine. No installation, app restart, source push or release publication is part of this audit.

## Research and limits

Before edits, agents attempted Google searches without opening a desktop browser; Google returned a consent page and no general search MCP was available. Apple's [camera-housing guidance](https://support.apple.com/en-us/102125) and [MacBook Pro product page](https://www.apple.com/macbook-pro/) loaded successfully. Functional changes preserve the camera-safe area and established native stack; the separate UI review records its visual/accessibility references.

Automated fixtures establish the covered regressions and current application behavior. They do not establish physical AirPods reconnection across every model, every third-party player's accessibility integration, real Spotify authorization, or byte-identical installer behavior in a fresh VM. Read-only optimization proposals remain separate from confirmed bug fixes.
