# Dynamic Island activity chooser

Research and implementation: 12 November 2026.

Google was queried through a background HTTP search for official Apple Dynamic Island design guidance. It returned a consent interstitial, so no Google result is claimed. Fresh copies of Apple's [Live Activities HIG JSON](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/live-activities.json), [expanded anatomy](https://developer.apple.com/tutorials/images/com.apple.HIG/type-expanded@2x.png) and [margin illustration](https://developer.apple.com/tutorials/images/com.apple.HIG/live-activities-margins@2x.png) were retrieved and the images inspected. Local captures are under ignored `artifacts/island-menu/research/`. The companion geometry/content/motion research includes official iPhone 14 Pro product photography, the macOS-notch comparison and an actual expanded media-player photograph.

The references establish an opaque black, detached housing with continuous rounded corners, inset content, balanced leading/trailing elements, legible medium-weight text and sparse controls. The chooser uses the existing measured 11-DIP top gap, 371-DIP expanded width, 44-DIP continuous-corner extent and retargetable island spring. It never creates a rectangular popup underneath the player. Clicking More or right-clicking an island morphs that same black housing into the chooser; closing it returns to the previous activity. The normal player keeps its 371×160 size.

Apple has no Winisland feature launcher. The 371×204 chooser, eight desktop activity destinations, setup/settings and pin are explicitly desktop adaptations, not a claim that Apple's system island has these actions or this height. Apple's HIG 84–160-point expanded live-activity height remains the reference for the music player. Balanced four-column activity controls avoid long Windows menu rows, submenu arrows, shortcut columns and scrollable command lists. Each activity has a restrained original vector glyph, medium-weight 11-DIP caption and a quiet selected surface; a real 44-DIP volume/mute row and quiet setup/pin glyphs keep controls usable without subdividing the housing into cards. Windows uses the existing licensed Inter font and original glyphs rather than bundling Apple's fonts or symbols.

Menu controls retain every previous destination and action. Volume readbacks preserve an active drag; exiting, collapsing, changing appearance or switching activity cancels capture. Escape first returns to the activity, and a subsequent Escape collapses. Arrow navigation, Tab, named automation peers, focus outlines, disabled unavailable volume/update states, pin status and reduced motion are supported. Pointer exit uses the existing collapse policy rather than leaving a separate popup behind.

The full private-desktop self-test exercises real control-local clicks, fixture-player volume/mute, all native destinations, close/Escape, setup/settings intentions, pin/unpin, compact right-click, live appearance switching and interrupted menu springs. Native rendered artifacts at 100%, 125%, 150% and 200% permit visual review of the detached contour, spacing, labels and focus. Final verification status and source identity are recorded in `communication.md`; this document by itself is not a passing runtime report.
