# Project optimization review

Reviewed 12 November 2026. The most promising improvements reduce repeated work at service boundaries: upload progress to WPF, browser frames to the native bridge, and audio discovery to the render thread. Preserve the existing native C#/WPF application and its measured Apple-inspired geometry.

This deliverable is a project-wide analysis and implementation roadmap. The optimization team made no production changes. Three reviewers examined media/device services, data/productivity services, and browser/build infrastructure; the primary reviewer examined window rendering, settings, updates, controls, existing research and verification evidence. Separate bug, UI and documentation teams are changing the same worktree. Their ownership and our handoffs are recorded in the local-only `communication.md`.

## Implementation and acceptance order

1. Start with progress coalescing, property-specific notifications and timeline text caching. They address repeated work with localized changes. Add callback/allocation counters to streaming and active-playback fixtures; retain immediate commands, terminal states and frame-smooth rail updates.
2. Reduce browser discovery/messages using a dedicated headless real-browser harness and exact candidate. Preserve navigation, open shadow roots, liveness, source ambiguity and command routing. The Node fixture supplies deterministic mechanism coverage alongside browser integration tests.
3. Implement audio/media caches and targeted Control Center readback. Measure active playback, route/source changes, event storms and delayed unrelated backends; preserve COM apartment ownership and latest-wins state.
4. Move ordered persistence/import I/O off WPF, then address startup/registration/CI. Keep commit/failure semantics explicit. Attempt low-priority math/geometry/font/harness changes only when profiling demonstrates worthwhile gains.

For each application change, freeze inputs and run `scripts/Build.ps1 -PrivateBuild -Verify` in a separate ignored candidate/snapshot. Compare before/after candidates with identical verifier and publish settings, alternating runs; record median and tail latency, allocations, CPU/private memory and handles appropriate to the workload. Treat any frame/interaction regression as a failed optimization. Installer behavior checks remain confined to a disposable Windows VM. Normal verification stays on the mandatory private desktop with no visible browser, global input, personal app restart or installation.

## Existing work to preserve

The project already has lazy secondary panels and Spotify automation startup, frozen bounded artwork detached from encoded buffers, fixed spectrum buffers, normalized browser matching, bounded shelf/notification/media data, streamed sequential uploads, debounced unchanged-note saves, demand-driven reminder scheduling, hidden-panel timer shutdown, 25 Hz latest-player-volume writes, API caching/backoff and specific build-flavor separation for ReadyToRun. Those are implemented strengths, not new findings. [RAM-OPTIMIZATION.md](RAM-OPTIMIZATION.md) retains its controlled earlier comparison; today's single run is not a replacement comparison.

Do not pursue forced garbage collection/working-set trimming, premature database/framework migration, wholesale removal of verification gates, unbounded geometry caches, weakened checksum/credential/identity validation or reduced animation cadence as automatic optimizations. The bounded datasets and current architecture favor removing demonstrated repeated work first.

Before the audit, a background Google query about Apple MacBook/macOS notch design reached Google's consent page; no search MCP was exposed. Apple's official [MacBook Pro page](https://www.apple.com/macbook-pro/) and [camera-housing guidance](https://support.apple.com/en-us/102125) returned HTTP 200. The latter requires controls/menu content to remain clear of the camera area. Existing measured project references remain applicable: retain camera spacing, exact silhouettes, native typography/scale, accessibility/focus, interrupted spring motion and reduced-motion behavior while optimizing their computation.
